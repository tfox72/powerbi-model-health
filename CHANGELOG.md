# Changelog

Versions v1 to v5 were built in one working session, each followed by independent code and skill reviews. Their scores are for "trustworthy on a first run, as far as can be verified without a live tenant." From 0.6.0 the notebook carries a version number, shown in its title and in every summary.

## 0.6.0 (v6, current)

A review against six guidelines. Each change below is listed under the guideline it serves.

**1. Fail in seconds, not after the scan**
- New **Preflight** step (Step 4). It stops before the scan for a missing lakehouse, an unknown workspace, or model names that match nothing, and lists the models that do exist. It warns, without stopping, when the first model can't be opened over XMLA, when a name is partly wrong, when two models share a name, and when the scope is large.
- Model names in `DATASETS` and `SKIP_DATASETS` are no longer case-sensitive.
- `WRITE_TO_LAKEHOUSE = False` is now a supported mode: results show in the notebook and nothing is saved.

**2. The notebook reads like a tool**
- The 1,070-line logic cell is split into six titled cells, so the Fabric table of contents can navigate it. Engine cells are marked to collapse their code.
- New **Results** step (Step 7) renders the summary as formatted markdown in the notebook. The plain-text copy for pasting moved to its own step (Step 9).
- The scan prints one line per model with its time, finding count and any failed steps.
- Settings are grouped by purpose, and the title cell says how to use the notebook in four steps.

**3. Safe to re-run**
- Each scan (Step 5) is a new run with its own Run Id. Before, re-running the scan reused the old Run Id.
- Saving is idempotent: running Step 8 twice for one run writes nothing twice, and after a failed table write it retries only the tables that failed.
- Change tracking excludes the current run, so re-running after a save can't compare a run with itself.

**4. Finish the documentation and DAX-review jobs**
- New `doc_worklist_<model>.csv`: one row per object that needs a description or comment, in priority order, with blank draft and approval columns and the object's lineage tag.
- The skill has a DAX review procedure with a full checklist (`references/dax-review-checklist.md`), and a documentation procedure with a style guide for DAX and Power Query (`references/documentation-style.md`).
- Documentation coverage in the summary now counts the same objects as the findings (auto-date and field-parameter tables are left out of both).

**5. One source of truth**
- The notebook exists once, in `notebook/`. The copy inside the skill is gone.
- `tools/build.py` builds the notebook from its source and packages the skill. `tests/test_package.py` fails if the notebook is out of date, if a reference file is missing or unmentioned, or if a package has the wrong layout.
- `examples/` holds sample output, regenerated by `tools/make_examples.py`.

**6. Packaged for where it runs**
- The skill folder is now `skills/powerbi-model-health/`, matching the skill's name, and holds only small markdown files.
- Two packages: `dist/copilot/` with `SKILL.md` at the zip root, and `dist/claude/` with the skill folder at the root. The v5 zip nested `SKILL.md` in a folder named `skill/`.
- New `copilot/agent-instructions.md`: the skill condensed to fit Agent Builder's 8,000-character instruction limit.

**Also**
- Dependency scan: a plain column or table that depends on another object is now followed as a dependency. Before, those rows were skipped.
- The unused table shows "hidden" or "visible" in place of True or False.
- Table writes work with both pandas 2 and pandas 3 string columns.
- Removed unused constants and the development helper scripts.

## v5
- **Query-log coverage check.** The logs raise confidence only when their coverage is verified. That means at least 14 days requested, monitoring data reaching back about that far, under the library's 50,000-query cap, and some queries logged if the model has reports. Otherwise they're marked "Partial" and don't raise confidence (objects they saw still count as used).
- **Ranking:**
  - Star-schema problems rank right after DAX issues.
  - Noisy BPA Performance rules rank with Maintenance.
  - Unused columns of 100 MB or more become Warnings at High/Medium confidence.
- **Robustness:**
  - Every analysis step is guarded.
  - Models with zero tables are handled.
  - DMV rows containing NaN are handled.
  - DAX names containing an escaped `]]` are parsed correctly.
- **Data dictionary:**
  - Adds relationships and incremental-refresh source M.
  - Splits into parts above ~150,000 characters.
  - Model shape now shows relationship counts.
- **Fewer false "unused" flags:** aggregation base columns (`AlternateOf`) and NAMEOF references in any calculated table now count as used.
- **BPA rules:** "Ensure tables have relationships" and "Consider a star-schema…" are dropped because the notebook's star-schema checks cover them. The "Remove auto-date table" fix now says to repoint visuals first.
- **Polish:**
  - Shorter per-row removal actions, with the procedure stated once.
  - Blank Errors when BPA didn't run.
  - Previous names shown for renamed objects.
  - Escaped markdown block characters.
  - The paste fallback cuts at a section boundary.
  - `top_findings.csv` includes the curated fix.
  - Lineage-tag changes between runs no longer show as Added + Removed.
  - Schema-enabled lakehouse table names are handled.
